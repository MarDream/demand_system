① 数据模型（新增 1 张表 + 加 1 列）

-- 分组只加在「数据表」这一层，Base 表不动
CREATE TABLE bitable_table_groups (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  base_id    BIGINT NOT NULL,   -- 所属多维表格
  parent_id  BIGINT NULL,       -- NULL=根层级，自关联
  name       VARCHAR(100) NOT NULL,
  sort_order INT NOT NULL DEFAULT 0,
  creator_id BIGINT NULL,
  created_at DATETIME,
  updated_at DATETIME,
  deleted_at BIGINT NULL,
  KEY idx_base_parent (base_id, parent_id)
);

-- 数据表挂到分组上（可空 = 未分组）
ALTER TABLE bitable_tables
  ADD COLUMN group_id BIGINT NULL AFTER base_id,
  ADD KEY idx_group (group_id);

「全部实体」「未分组」都是前端虚拟节点，不落库；删除走 deleted_at 软删除，与项目既有约定一致。

② 接口（新增 TableGroupController，与 BitableTableController 同域）

  • GET/api/v1/bitable/bases/{baseId}/table-groups → 树（含各节点表数）
  • POST…/table-groups 建分组 {name, parentId}
  • PUT…/table-groups/{id} 重命名
  • PUT…/table-groups/{id}/move 移动 {parentId, sortOrder}
  • DELETE…/table-groups/{id} 删除分组
  • PUT/api/v1/bitable/tables/{id}/group 数据表归组 {groupId}

树接口一次返回全量（单个 Base 的表量级为几十到几百，不做懒加载），折叠状态由前端本地维护。

③ 交互规则（原型已实现）

  • 任意层级嵌套：parent_id 自关联，无深度上限
  • 「未分组」按需显示：该层级没有未归组数据表时自动隐藏（对齐你的截图：CRM 下无未分组）
  • 拖拽数据表 → 落到分组 = 归入该分组；落到「未分组」= 移出分组
  • 拖拽分组 → 改父级 / 调同级顺序；拖到自身或子孙节点禁止（防环，有红色提示）
  • 「全部实体」只读：不可拖入、不可改名删除，点击=平铺全部数据表
  • 搜索：命中分组名或表名，自动展开命中路径并高亮
  • 折叠状态按 base 存 localStorage，下次进入保持
  • 删除分组：子分组与数据表上移到父级，不级联删除

④ 需要你拍板的点

  • 删除非空分组：子项上移到父级（原型方案）／ 弹窗让你选「一并删除数据表」？
  • 分组能否建在「未分组」下：原型禁止（未分组是虚拟节点）
  • 权限：分组是否直接跟随 Base 成员权限，还是要单独的「分组可见性」？
  • 侧边栏是否显示数据表叶子节点：原型只在右侧列表展示（对齐截图）；若要左侧直接看到表名，树会更深更长
  • 是否要拖拽排序手柄、右键菜单，还是保持原型里的悬浮 ··· 菜单
