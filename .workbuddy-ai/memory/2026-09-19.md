# 多维表格：左侧目录收起后遮挡右侧内容（已修）

**现象**（用户截图）：多维表格页左侧目录收起后，展开按钮压住右侧内容左上角，
仪表盘选择器「数据仪表盘」的第一个字被盖住。

**根因**：`views/bitable/index.vue` 里展开按钮是
`position:absolute; top:10px; left:10px`，挂在 `.bitable-layout`（`position:relative`）上。
收起时 `.bitable-layout.is-sidebar-collapsed` 变成单列 `minmax(0,1fr)`，右侧卡片铺满整行，
而卡片 header 的 `padding:10px 16px` 让选择器正好落在 x≈246 —— 按钮占 240~269，重叠 23px。

**修法（走正常流，不靠调 z-index/偏移量）**：
- `.bitable-layout.is-sidebar-collapsed { grid-template-columns: auto minmax(0, 1fr); }`
  —— 收起后左侧留一条**窄轨道**（宽度由按钮自身撑开）。
- `.bitable-sidebar__expand` 去掉 `position/top/left`，改 `align-self:start; margin-top:10px`
  —— 按钮成为 grid 第一项，右侧内容整体右移，**物理上不可能重叠**。
- 因为按钮本来就是 `v-if="treeCollapsed"`（只在收起态存在），所以无需额外条件类。
- 附带修好了列表态（`.bitable-list__header` 的「全部」标题）同样的遮挡。

## AI 助手知识库问答：角标渲染 + 引用来源过滤

### 用户问题

1. 问「涉及i莞家小程序的需求有哪些」时，引用来源带出了「机械臂人脸识别对接」，与小程序无关 → RAG 召回准确性差。
2. 引用来源已编号，但回答正文里没有把这些编号以角标形式代入。

### 根因定位

- **角标渲染**：后端已有 `replaceCitationLinks` + `MarkdownContent` 的完整链路，
  但流式阶段 `message.citations` 要到 `done` 事件才落盘，生成过程中 `[4]` 是裸文本 → 用户误以为没有角标。
- **引用来源噪音**：`citations` = 全部召回结果（含弱相关长尾），其中部分文档模型根本没引用，
  照样列在「引用来源」里 → 出现无关需求。
- **编号错位风险**：`buildContext` 把 `documentId=null` 的片段也编了号，而 `buildCitationReferences`
  过滤掉了它们，导致后续文档编号整体偏移。
- **归一化缺失**：模型常写 `（资料[4]）`、`【资料4】`、`[资料4]`，正则 `\[(\d+)\]` 匹配不到 → 无法渲染。

### 修复

**后端**：
- `AssistantServiceImpl`：`actions` 事件补 `citations`（在 `streamAnswerWithReasoning` 之前下发）。
- `KnowledgeSearchServiceImpl.retrieve`：`citations` 收敛为「真正进入 LLM 上下文的资料」
  （`selectContextResults(results)`），弱相关长尾只留在结果列表，不混进引用来源。
- `KnowledgeConfig`：新增 `contextRelativeFloor`（默认 0.4），与 `contextMinScore` 取较大值生效，
  自适应砍掉高分结果后面的弱相关长尾。
- `RagAnswerServiceImpl.buildContext`：编号只分配给有 `documentId` 的片段，
  null-doc 片段标注「无编号，不可引用」，避免后续编号被挤位。
- 系统提示词追加约束：角标直接写在结论后，不要写成 `（资料[1]）`；无编号资料不插角标。

**前端**：
- `stores/assistant.ts`：`onActions` 接收并写入 `payload.citations`，流式首帧即可渲染角标。
- `utils/markdownRender.ts`：归一化模型输出的编号写法（`（资料[4]）`、`【资料4】`、`[资料4]`、
  全角括号、裸前缀）→ 统一收敛成 `[N]` 再替换为 `sup.citation-ref`。
- `SystemAssistant.vue`：`citationListOf` 按正文角标过滤引用来源列表，只展示正文真正引用过的编号；
  无角标时回退展示全部来源。编号沿用原始序号，保证与角标一一对应。

**配置**：`application.yml` 显式声明 `knowledge.context-min-score` / `context-relative-floor` /
  `similarity-threshold`，方便线上调参。

# 工作流配置：编辑时间语义修正 + 新增「发布时间」列

**需求**（用户截图，红框圈住「编辑时间」）：1）编辑时间应是最后一次编辑的时间；2）增加一个「发布时间」，即启用时间。

## 根因（关键，和直觉不同）

「编辑时间」恒等于「创建时间」**不是**因为 `updated_at` 没被写入，而是因为

返回的是 DTO，`BeanUtils.copyProperties(entity, dto)` 只拷同名字段，字段缺失 → JSON 里没有 `updatedAt`
→ 前端 `row.updatedAt ? ... : row.createdAt` 永远走兜底。
实测接口返回字段清单里确认无 `updatedAt`；`changeLog` 同样不在 DTO 里，所以「最近发布」列（渲染 `row.changeLog`）恒为空。
**排查手法**：在已登录页面里 `fetch` 该接口打印 `Object.keys(rows[0])`，比读前端类型声明可靠

  所以这类路径必须显式 set，光改 DB 没用。

# 修复：保存工作流配置 500（`POST /workflows/0/config` NPE）

**现象**：用户在画布保存草稿时 500，error.log 报
`NullPointerException: Cannot invoke "String.length()" because "prefix" is null`
→ `WorkflowChangeLogBuilder.stripPrefix:512` ← `putTerminalName:370` ← `buildNodeNameMap:362` ← `diff:130`。

**根因**：`diff()` 第 130 行 `buildNodeNameMap(newNodes, newEdges, null)` 故意传 **prefix=null**
（新配置的节点/连线 ID 没有 `v{versionId}_` 前缀），但边引用**裸终态 ID**（`cancelled`/`accepted`/`rejected`，
前端校验器 `validateGraph` 明确允许这种"连线指向终态而不存在对应节点"的形态）时，
`putTerminalName` → `stripPrefix(id, null)` → `id.startsWith(null)` 必炸。
属于**正常业务形态触发的必崩路径**，不是脏数据。

**修复**（`WorkflowChangeLogBuilder.stripPrefix`）：`prefix == null` 时直接返回原 id
（语义本来就是"没有前缀可剥"），三行改动，其余调用点（传真实前缀的）行为不变。

**验证**：
1. plexus 绕过编译通过；并行会话 22:37 重启后端，新类自动生效。

   —— 说明 `putTerminalName` 现在真的把 `accepted` 映射成了「已通过」。
3. 用原始 payload 恢复 v15（configHash 与原值一致 `720a38d3…`），删掉复现产生的
   两条 `workflow_history`（id 13/14），库恢复原状。

**教训**：`stripPrefix(id, prefix)` 这种"可选前缀"参数，`null` 必须显式处理 ——
调用方 `buildNodeNameMap(newNodes, newEdges, null)` 的 null 是**有意传的**，不是漏传。

**三个关键坑**（详见 topics/bitable.md）：
1. VO 是纯手写 POJO，加字段必须连 getter/setter —— 只加字段 MapStruct 静默不映射，
   接口恒返回 null，编译不报错、DB 值是对的，症状像「move 没生效」。
2. `isLeafKind` 要 type predicate，否则 `emit('move-leaf', {kind: source.kind...})` 报 TS2769。
3. 回归脚本 try 块的异常被 finally 的 `process.exit` 吞掉会假绿 —— 必须 catch 落 FAIL；
   断言要轮询等待后端真值，不能赌固定 sleep。
