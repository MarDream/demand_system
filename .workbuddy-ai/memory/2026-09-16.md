## 修复：Base 分组树「移动到分组」后归属不生效

用户报：未分组的多维表格移到自定义分组后 ① 分组下看不到它 ② 它仍留在「未分组」。

### 根因（一行 SQL 漏列）
`BitableBaseMapper.xml` 的 **三个 SELECT 全部漏查 `group_id`**（`selectByCreator` /
`selectByMember` / `selectDetailById`），而 `bitable_bases.group_id` 在 DB 里是对的。
于是 `GET /api/v1/bitable/bases` 返回的 `groupId` **恒为 null** →
前端 `basesOfGroup()` 永远匹配不到 → 全部 Base 落进「未分组」，自定义分组永远空
（右侧一直「共 0 个」）。

**写操作是好的、读操作是坏的**，所以只看 DB 会误判成"没保存"。对照证据：
- DB：`bitable_bases` id=1 项目管理 `group_id=2`、id=17 周KPI `group_id=2`（绩效考核）
- 修复前 API：11 条 base 里 `groupId != null` 的 **0** 条，`项目管理.groupId = null`
- 分组树接口 `listGroupTree()` 走 MP 自动 SQL（含全列）→ 分组徽标计数 **是对的**（绩效考核=2），
  只有展开后的子节点是错的 —— **"徽标有数、展开为空"就是这个 bug 的指纹**。

### 修复
`BitableBaseMapper.xml` 三处 SELECT 补 `group_id`（`selectDetailById` 是 `GROUP BY b.id` +
`ONLY_FULL_GROUP_BY`，按主键函数依赖合法，已用 SQL 直跑验证）。改后 API：11 条中 2 条带
`groupId`，未分组 9 条，`绩效考核.baseCount=2`。

### 回归
新增 `scripts/verify-base-group-move.cjs`（**32 项**，自清理：临时分组 `__MOVE_TGT` 建→用→删，
Base 归位）。断言要点：用「最近更浅层容器」算法判定每个 Base 的归属容器，
覆盖「未分组→自定义分组」「自定义分组→未分组」往返 + 刷新持久化 + 右侧范围计数/卡片。
`verify-base-group-rename.cjs` 17、`verify-editor-breadcrumb-and-table-rename.cjs` 29 复跑全绿。

**踩坑**：点击分组行会**同时**触发选中和 `toggleExpand`（折叠），后续按 `data-key` 定位其下
Base 会找不到 → 脚本里加了 `ensureExpanded(key)` 读 `.bgtree-node__chev.is-open` 再补点一次。

### 已知遗留（未改，告知用户）
`listGroupTree()` 的 `baseCount/totalBaseCount` 用 `baseMapper.selectList(null)` 统计**全局**，
而展开的子节点来自 `listBases()`（按创建者/成员**过滤过**）。多人场景下会出现
"徽标 5、展开只有 2"。`deleteGroup` 的确认文案也复用这个计数，改成按人过滤会让提示少报，
所以本轮刻意不动。

## 第二阶段：跨视图取值口径收敛 + 三处真 bug 修复

### 核心问题
看板 / 画廊 / 日历 / 甘特各写了一套取值逻辑，字段属性在它们那里完全不生效。
最典型的不一致：**进度 85 在网格显示 `85%`，在看板显示 `8500%`**（KanbanView 里
`Math.round(valueNumber * 100)`），而网格的百分比约定是**不做 100 倍缩放**。

### 收敛方案（架构约定，后续改视图必须遵守）
- `utils/bitableFieldConfig.ts` 新增**唯一取值口径**：
  - `formatCellDisplay(field, cell): string` —— 所有视图展示单元格文本都走它；
  - `resolveRecordTitle(fields, record, preferredFieldId?)` —— 卡片标题；
  - `formatDateCell(raw, config)` —— 日期格式化（从 `bitableCellRenderers.ts` 的私有
    `formatDateValue` 提上来共享）。
- **禁止再在任何视图里自己写 `cell.valueText ?? cell.valueNumber ?? ...` 的兜底链**。
  新增视图直接调这两个函数。
- `KanbanView` / `GalleryView` / `CalendarView` / `GanttView` 已全部改为调用共享函数。

### 修掉的真 bug
1. **日期占位符只认小写**（影响所有视图 + 网格）：`formatDateCell` 原来只替换 `yyyy|MM|dd`，
   但 `DATE_FORMAT_OPTIONS` / `createDefaultFieldConfig` 用的是**大写** `YYYY-MM-DD`，
   于是日期列原样吐出 `YYYY/03/DD`。
   → 现在同时支持 `YYYY`/`yyyy` 与 `DD`/`dd`，并支持 `hh`（12 小时制）+ `A`（AM/PM）。
   **注意 Element Plus 的 `value-format` 用 `yyyy-MM-dd`（小写），两套写法都要认。**
2. **KanbanView `case 'check'` 是死代码**：字段类型实际是 `checkbox`，`check` 永不命中。
   （`GridView` 里 `check`/`checkbox` 两个都写了，所以没暴露。）
3. **KanbanView 评分** `'★'.repeat(valueNumber)` 忽略 `maxRating` / `ratingIcon` / `allowHalf`。

### 新增能力
- **`BitableRelation` 渲染器**：`user` / `group` / `link` / `bidirectional_link` 的值是
  id 数组或 `[{id,name}]`，`String(数组)` 会渲染成 `1,2` / `[object Object]`。
  现在统一 `relationText()` 解析；**并且这些列的 `editRender` 置 null** ——
  给它们文本编辑器时，`handleEditClosed` 会把 `String(数组)` 写回库破坏关联。
  `buildRecordData` 也改为对 user/group 保留原始 JSON。
- **`RecordEditDialog` 支持 `multi_select`**（此前 `supportedTypes` 里漏了，多选在记录弹框里
  根本不可编辑）：多选下拉 + `valueJson` 数组写回；`save` emit 与 `editor.vue#handleRecordEditSave`
  的类型都补了 `valueJson`。
- **`RecordEditDialog` 只读区改用 `formatCellDisplay`**：此前 `JSON.stringify(结构化值)`
  会把附件/关联/人员显示成裸 JSON。

### 后端：字段/表删除要清字段权限（无外键）
`bitable_field_permissions` 没有外键，删字段/删表**不会级联**，会留下指向已删字段的孤儿行
（唯一键还会挡住同角色再次配置）。新增 `BitableFieldPermissionMapper.deleteByFieldId/deleteByTableId`
+ service 同名方法，并接进 `BitableFieldServiceImpl#deleteField` 与
`BitableTableServiceImpl#deleteTable`。已用 SQL 清掉历史孤儿行。

### 踩坑：创建类接口返回的是**裸 ID**，不是对象
`POST /bitable/bases`、`/bases/{id}/tables`、`/tables/{id}/fields`、`/tables/{id}/records`、
`/tables/{id}/views` 的 `data` 都是 **number**，但前端 `api/modules/bitable.ts` 的 TS 类型
声明成了 `BitableBase` / `BitableTable` / ...（类型撒谎）。
`editor.vue#handleCreateView` 已经用 `typeof x === 'object' ? x.id : Number(x)` 兜住了，
写脚本时也要同样兜（本次第一版脚本就栽在这，误判成"创建失败"）。
